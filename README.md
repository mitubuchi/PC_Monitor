# PCMonitor

常駐型のキーロガーとバックドアの「疑わしい候補」を洗い出す、Windows 用の点検ツール。C# / WPF。

Windows Defender を置き換えるものではない。Defender が「既知の悪いもの」を止めるのに対して、
PCMonitor は「常駐している・通信している・署名が無い」といった**条件の重なり**を見て、
人が確認すべきものを危険度順に並べる。

- 出すのは「確認すべき候補」で、「これはウィルスだ」という断定ではない
- **「何も出なかった」は「安全」を意味しない**（[限界](#限界)）
- 見つけて示すまでが役目。削除・隔離・プロセスの強制終了・外部への送信は、意図して持たせていない

設計の全体と、実機で確かめた結果は [Docs/design.md](Docs/design.md) にある。

## 何を見るか

| 点検 | 見るもの |
|---|---|
| 常駐箇所 | Run キー、スタートアップ、サービスとドライバー、タスク スケジューラ、WMI イベント購読、Winlogon、AppInit_DLLs、IFEO |
| プロセス | 実行ファイルの署名と置き場所、ウィンドウの有無、親子関係 |
| 通信 | TCP の待ち受けと接続、UDP のバインド（プロセスごと） |
| 読み込み DLL | 署名済みのプロセスに載っている、署名の有効でない DLL |
| メモリ | 実行できるのに、実行イメージではない領域（JIT を持たないプロセスについて） |
| キー入力 API | 見張っている間に呼ばれた、キーボード フックの設置や生入力の登録（管理者のみ） |

同じ実行ファイルが複数の点検に出てきたら、1 件にまとめて兆候を合算する。
兆候には、点だけでなく、人が確かめられる根拠の文が必ず付く。

| 危険度 | 点 |
|---|---|
| 高 | 60 以上 |
| 中 | 30〜59 |
| 低 | 10〜29 |
| 情報 | 9 以下 |

兆候は 1 つずつでは弱く、重なったときに上がる。単独で「高」になる兆候は作っていない。
点数と、それを付ける条件は [Docs/design.md](Docs/design.md) の §6 と §11。

## ほかの PC で使う

.NET の実行環境ごとまとめた ZIP を作って渡す。受け取った PC に .NET を入れる必要は無い。

```
pwsh -File tools\publish.ps1
```

`artifacts\publish\PCMonitor-<版>-win-x64.zip` ができる（約 77 MB、展開すると約 190 MB）。
.NET 10 の実行環境を同梱する。同梱する版は ZIP を作ったときの SDK の版なので、.NET にセキュリティ修正が出たら作り直す。
中身は画面（`PCMonitor.exe`）、コンソール版（`pcmonitor-cli.exe`）、使う人向けの説明書（`README.txt`）。
検証プログラム（Probe）は入れていない。説明書の元は [dist/README.txt](dist/README.txt)。

| 条件 | 動くか |
|---|---|
| Windows 11 25H2（x64） | 確かめた |
| Windows 11 のほかの版、Windows 10 1607 以降（x64） | 動くはずだが、確かめていない |
| ARM64 の PC | x64 のアプリとして動くはずだが、確かめていない |
| 32 ビット版の Windows | 動かない |

**使えない機能や、確かめていない条件は、その PC で調べて画面に出す。**
スキャンの結果の注意書きの先頭に、その PC の条件（Windows の版、CPU、権限、実行環境）と、
使えない機能が並ぶ。書き出した JSON にも入る。

| 機能 | 使えない条件 | 使えないときの画面 |
|---|---|---|
| キー入力 API の監視 | 管理者でない / Windows に監査のイベントの定義が無い | ボタンが押せず、理由が出る |
| 管理者でないと見られる範囲 | 通常の権限で起動したとき | 見られなかった件数が注意書きに出る |
| 常駐箇所・WMI の一部 | 会社の PC などで、ポリシーで止められているとき | その箇所が「点検できなかった」として出る |

使う人に向けた注意（SmartScreen、ZIP のブロックの解除、会社の PC、ウイルス対策ソフトとの関係）は、
ZIP の中の `README.txt` に書いてある。

## 必要なもの（開発）

- Windows 10 / 11（64 ビット）。動かして確かめたのは Windows 11 25H2 だけ
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)（10.0.100 以降。`global.json` で指定している）

管理者権限なしで SDK を入れるときは、Microsoft の ZIP を `%LOCALAPPDATA%\Programs\dotnet10` に展開する。
その場合、ビルドはその `dotnet.exe` で行い、開発用のビルドを起動するときは `DOTNET_ROOT` をその場所に向ける
（[Docs/design.md](Docs/design.md) §15）。`tools\` のスクリプトは、この置き場所を自分で探す。

## ビルドと起動

```
dotnet build PCMonitor.sln
```

画面:

```
src\PCMonitor.Wpf\bin\Debug\net10.0-windows10.0.19041.0\PCMonitor.exe
```

通常の権限で起動でき、見られる範囲だけ点検する。ほかの利用者とシステムのプロセス、一部のタスク、
WMI イベント購読は、管理者でないと見られない。画面の「管理者として再起動」で昇格する。

コンソール版:

```
src\PCMonitor.Cli\bin\Debug\net10.0-windows\pcmonitor-cli.exe --min-level medium --verbose
```

| オプション | 内容 |
|---|---|
| `--min-level info\|low\|medium\|high` | この危険度以上を表示する（既定は `low`） |
| `--verbose` | 根拠の文も表示する |
| `--find <文字列>` | 名前かパスに含むものだけを、根拠付きで表示する |
| `--json <パス>` / `--csv <パス>` | 結果を書き出す |
| `--data-dir <フォルダー>` | 許可リストと「前回の結果」の置き場所を変える |
| `--no-save` | 「前回の結果」として保存しない |
| `--verify <ファイル>` | そのファイルの署名の検証結果だけを表示する |
| `--check-env` | その PC の条件と、使えない機能を表示する |
| `--memory-map` | プロセスごとに、実行イメージではない実行可能な領域と、JIT の手がかりを並べる |
| `--monitor-keys <秒>` | その秒数だけキー入力 API を見張ってから点検する（管理者のみ） |
| `--read-etl <パス>` | 記録済みの `.etl` から読んだ呼び出しを、見張りの結果として点検に渡す |

## 画面の使い方

1. ［スキャン］を押す。数秒で終わる
2. 一覧は危険度の高い順。行を選ぶと、下に根拠が出る
3. 確かめて問題の無いものは「許可リストへ追加」で一覧から外せる

選んだ項目にできる操作は、「ファイルの場所を開く」「ハッシュをコピー」「許可リストへ追加」だけ。

- **許可リスト**は、パスとハッシュの組で持つ。中身が変わると許可は外れ、変わったことが挙がる
- **前回との差分**: 2 回目からは、前回に無かった項目に「新規」の印が付く
- **ハッシュ**は、VirusTotal などで調べるときに自分で貼り付ける。このツールは外へ送らない

### キー入力 API の監視

管理者として起動すると、「キー入力 API の監視を開始」を押せる。見張っている間に呼ばれた
キーボード フックの設置や、キーボードの生入力の登録を拾い、次のスキャンで、呼んだプログラムの行に付ける。

- **分かるのは、見張りを始めてから止めるまでの間に起きた呼び出しだけ。**
  すでに設置されているフックは出てこない。疑わしいものは、見張りを始めてから起動し直す
- 受け取るのは「誰が、どの API を、どういう形で呼んだか」で、キー入力そのものは流れてこない

## 保存するもの

`%LOCALAPPDATA%\PCMonitor\` に置く。どちらも JSON（UTF-8、BOM 無し）。

| ファイル | 中身 |
|---|---|
| `allowlist.json` | 許可リスト |
| `last-scan.json` | 前回の結果（差分に使う）。項目ごとの点と兆候の名前、見張りで拾った呼び出し |

## 構成

```
PCMonitor/
  ├─ Docs/design.md              設計と、実機で確かめた結果
  ├─ PCMonitor.sln
  ├─ src/
  │   ├─ PCMonitor.Core/         点検ロジック。UI に依存しない
  │   ├─ PCMonitor.Cli/          コンソール版（pcmonitor-cli.exe）
  │   └─ PCMonitor.Wpf/          画面（WPF + ReactiveUI。PCMonitor.exe）
  ├─ tests/
  │   ├─ PCMonitor.Core.Tests/   採点と解析の単体テスト
  │   └─ PCMonitor.Probe/        検知を実測するための、無害な検証プログラム
  ├─ dist/README.txt             配布する ZIP に入れる、使う人向けの説明書
  └─ tools/                      配布用の ZIP を作るスクリプトと、管理者のターミナルで実行する確認用のスクリプト
```

Core の中は、**集める**（`Collectors`、`Monitoring`）と**判断する**（`Scoring`）を分けてある。
採点の規則はあとで必ず調整することになるので、事実の取得を巻き込まずに直せるようにしている。

## 確かめ方

「動くはず」で済ませず、無害な検証プログラム（Probe）を実際に動かして、検知されることを実測している。

```
dotnet test tests\PCMonitor.Core.Tests
```

Probe は、キーロガーやバックドアが取る形を**害の無い形で**わざと行う。**キー入力の取得は行わない。**
終了時に自分の登録を消す。

| オプション | ふるまい |
|---|---|
| `--run-key` | HKCU の Run キーに自分を登録する |
| `--listen <ポート>` | `0.0.0.0` のポートを待ち受ける（接続を受けても何もしない） |
| `--spawn-shell` | `cmd.exe` を子として起動し、待たせておく（何も実行させない） |
| `--alloc-exec` | 子の `cmd.exe` の中に、書き込みも実行もできる領域を確保する（確保するだけ） |
| `--key-apis` | キーボード フックなどの API を、何も取得しない形で呼ぶ（設置してすぐ外す） |

通常の権限で確かめる例:

```
tests\PCMonitor.Probe\bin\Debug\net10.0-windows\PCMonitor.Probe.exe --run-key --listen 47631 --seconds 60
src\PCMonitor.Cli\bin\Debug\net10.0-windows\pcmonitor-cli.exe --no-save --find PCMonitor.Probe
```

キー入力 API の監視は、管理者のターミナルで確かめる。見張り・Probe の実行・点検をまとめて行う。

```
pwsh -File tools\monitor-probe.ps1
pwsh -File tools\monitor-probe.ps1 -Ambient -Seconds 120    Probe を動かさず、ふだんの状態を見張る
```

Windows PowerShell 5.1 は、既定ではスクリプトを実行しない。`pwsh -File` で呼ぶか、
`powershell -ExecutionPolicy Bypass -File …` とその 1 回だけ指定する（PC の設定は変えない）。
結果は `artifacts\etw\` に書かれる（git には入れない）。

実測の結果は [Docs/design.md](Docs/design.md) の §12 と §11.5。

## 限界

- **カーネルレベルのルートキット**: 隠されたプロセスやファイルは見えない
- **正規ツールの悪用**: 署名済みのツールだけで組まれた侵入は、点が上がりにくい
- **JIT を持つプロセスへのインジェクション**: ブラウザーや .NET・Electron のアプリの中は、メモリの点検では見えない
- **ハードウェアのキーロガー**: ソフトからは検知できない
- **スナップショットであること**: 点検した瞬間に動いていないもの、張っていない接続は見えない
- **キー入力 API の監視**: 見張りを始める前から設置されていたフックは見えない
- **失効の確認をしない**: ネットワークに出ないので、失効した証明書の署名は「有効」と出る
- **管理者でも見えないプロセスがある**: 保護されたプロセスは、DLL とメモリを確かめられない

## やらないこと

| やらないこと | 理由 |
|---|---|
| リアルタイム保護（開いた瞬間に止める） | カーネルのドライバーと Microsoft の署名が要る |
| 削除・隔離・プロセスの強制終了 | 誤検知で正規ソフトを壊す |
| 検体のアップロード | 手元のファイルを外部へ送ることになる |
| ほかのプロセスのメモリの中身を読むこと | 点検ツール自身が、セキュリティ製品に疑われる動きをすることになる |
