# ランサムウェアの侵入経路・手口・中小企業での注意点

2026-11-15 の会話をまとめたもの。数値は警察庁
「[令和8年上半期におけるサイバー空間をめぐる脅威の情勢等について](https://www.npa.go.jp/publications/statistics/cybersecurity/data/R8kami/R08_kami_cyber_jousei.pdf)」
（令和8年9月、警察庁サイバー警察局）による。ページ番号はこの資料のもの。

---

## 1. ランサムウェアはどこから入ってくるか

メール経由が主流だったのは以前の話で、いまは**インターネットに出ているリモート接続の入口**から入られる。
被害組織へのアンケート（統計編 p.143）では次のとおり。

| 侵入経路 | 令和8年上半期（36件） | 過去5年（485件） |
|---|---|---|
| VPN 機器 | 50%（18件） | 60%（293件） |
| リモートデスクトップ | 25%（9件） | 22%（105件） |
| 不審メール・添付ファイル | 0件 | 5%（24件） |
| その他 | 25%（9件） | 13%（63件） |

攻撃者は**未修正の脆弱性**や**漏えいした ID・パスワード**を使って入る（本文 p.10）。
最近は次の傾向もある。

- 盗まれた認証情報や侵入済みの足場が売買されており、攻撃者自身が入口を探すとは限らない
- 侵入から暗号化まで数日〜数週間の時間差がある
- 本社より、管理の甘い子会社・海外拠点・委託先から入られる

- 規模別：中小企業 79件・大企業 31件・団体等 13件（**中小企業が約6割**）
- 業種別：製造業 37件が最多。卸売・小売 15件、情報通信 9件、不動産・物品賃貸 9件、医療・福祉 9件、建設 8件

### 2.4 実際に起きた事案（資料編 p.97 ほか）

| 時期 | 被害先 | 内容 |
|---|---|---|
| 2月 | 医療機関 | ランサムウェアでナースコールが停止。患者約13万人の個人情報が漏えい |
| 2月 | 政府機関・交通・金融など | 親ロシア系グループの DDoS 攻撃でウェブサイトが閲覧不能に |
| 3月 | 大手製造業 | 不正アクセスで顧客・従業員約8.8万件の個人情報を取得された |
| 4月 | 政府機関 | 大容量ファイル転送サーバーへの不正アクセス。個人情報漏えいの可能性 |
| 4月 | 鉄道業界団体 | ファイル転送サービスの脆弱性を突かれ、利用者の個人情報が漏えい |
| 5月 | 研究機関 | ウェブサーバーに不正アクセスの痕跡 |
| 6月 | 大手通信事業者 | ISP 向けメールシステムから、メールアドレス・パスワードなど約1,200万人分が漏えい |

このほか、15歳の少年が生成AIで手直しした攻撃プログラムで動画配信サービスの会員約4.68万アカウントを退会させた事件、
19歳の会社員がAIでランサムウェアを作成して逮捕された事件がある（本文 p.28）。

**まとめると**、件数ではフィッシングと詐欺が圧倒的に多く、組織1件あたりの損害と情報漏えいでは
ランサムウェアと不正アクセスが重い。漏えいの多くは、VPN 機器やファイル転送サーバーなど
**インターネットに出ている機器の脆弱性**から起きている。

## 3. ランサムウェアはどう破壊するか

いきなり暗号化されるのではなく、**入り込んでから時間をかけて準備し、最後に一気に壊す。**

| 段階 | 攻撃者がすること | 狙い |
|---|---|---|
| ① 侵入 | VPN 機器の脆弱性や漏れた ID・パスワードで入る | 入口の確保 |
| ② 権限の奪取 | 管理者アカウント（とくに Active Directory のドメイン管理者）を奪う | 全台に手が届くようにする |
| ③ 防御の無効化 | ウイルス対策ソフト・EDR・ログ取得を止める | 検知されないようにする |
| ④ 内部探索 | ファイルサーバー・データベース・バックアップの場所を調べる | 何を壊せば一番困るかを知る |
| ⑤ データ持ち出し | 重要データをクラウドなどへアップロードする | 「公開する」と脅す材料（二重恐喝） |
| ⑥ 復旧手段の破壊 | バックアップ、ボリュームシャドウコピー、復元ポイントを消す | 自力で戻せなくする |
| ⑦ 暗号化 | 夜間・休日に管理ツールで全台一斉に実行する | 気づいたときには手遅れにする |
| ⑧ 脅迫と痕跡消し | 脅迫文を置き、ログやツールを消す | 支払わせる、追跡させない |

- **本当の破壊は⑥のバックアップ潰し。** バックアップから復元できなかった29件のうち、
  14件はバックアップごと暗号化・消去されていた（ほかに運用不備8件、その他7件。統計編 p.149）
- **⑦の前に止めれば被害はほぼ出ない。** ②〜⑤の段階で、管理者アカウントの不審な使用、
  大量のデータ送信、セキュリティ製品の停止といった兆候が出る
- **暗号化しない手口もある。** データを盗むだけで公開を予告して脅す（本文 p.9）

## 4. 暗号化の特徴

### 4.1 ハイブリッド暗号（ほぼすべてに共通）

```
ファイルごとに使い捨ての鍵を作る
  └ 共通鍵暗号（AES や ChaCha20）でファイル本体を暗号化     ← 速い
      └ 使い捨て鍵を攻撃者の公開鍵（RSA や楕円曲線暗号）で暗号化してファイルに添える
                                                         ← 秘密鍵は攻撃者だけが持つ
```

- 共通鍵暗号は速いので、大量のファイルを短時間で暗号化できる
- 公開鍵で鍵を包むので、被害者の PC には復号に必要な秘密鍵が残らない
- 標準の暗号をそのまま使っているので、**正しく実装されていれば秘密鍵なしには解読できない**

### 4.2 速さを優先する工夫

| 工夫 | 内容 |
|---|---|
| 部分暗号化（間欠暗号化） | ファイルの先頭だけ、または一定間隔で一部だけを暗号化する。それでもファイルは開けなくなる |
| マルチスレッド | CPU のコアを使い切って並行で暗号化する |
| 対象の選別 | OS の動作に要るファイルは避け、文書・データベース・仮想マシンのディスクを狙う |
| 使用中ファイルの解放 | データベースやバックアップのサービスを止めてから暗号化する |

### 4.3 仮想化基盤をまとめて狙う

VMware ESXi などの仮想化基盤そのものを暗号化する型が増えている。
仮想マシンのディスクを暗号化すれば、その上の何十台ものサーバーが一度に止まる。

### 4.4 復号できる場合

基本は無理で、まれに例外がある。

- 鍵の作り方が甘いなど**実装の欠陥**があれば復号できることがある
  （警察庁のサイバー特別捜査部による復号の例がレポートのコラムにある。p.54）
- 捜査で攻撃グループのサーバーを押さえて鍵を回収し、無料の復号ツールが公開されることがある（No More Ransom など）
- 身代金を払っても戻る保証はない。復号ツールが不完全だったり、払ったうえでデータを公開されたりする

## 5. 中小企業で PC を個別管理している場合

「PC が個別管理なら、侵入されても先へ進みにくいのでは」という問いへの答え。

### 5.1 当たっている部分

Active Directory でまとめて管理していなければ、「ドメイン管理者を奪って全台を一斉に暗号化する」手口は使えない。
大企業の被害が大きくなるのは一元管理を逆用されるからなので、**横に広がる力は確かに弱い。**

### 5.2 それでも被害が出る理由

**(1) 横に広がらなくても、1台で共有フォルダーまで壊せる**

感染した PC から見えている共有フォルダーや NAS は、その PC のファイルと同じように暗号化される。
他の PC に侵入する必要はない。

```
PC 1台が感染
  └ 割り当てたネットワークドライブ（Z: など）
  └ ファイルサーバー・NAS の共有フォルダー
  └ 同期している OneDrive / Dropbox / Google ドライブ
      → 全社の業務データがまとめて暗号化される
```

**(2) 「個別管理」でも実は同じパスワード**

- 全 PC のローカル管理者が同じパスワード
- NAS・ルーター・複合機の管理画面が初期パスワードのまま
- ブラウザーにパスワードを保存している

1台で奪った認証情報が他の機器でも通れば、AD がなくても広がる。

**(3) 入口は PC ではないことが多い**

| 入口 | 中小企業でありがちな状態 |
|---|---|
| ルーター・VPN 機器 | 導入時のまま更新されていない。誰が管理者か分からない |
| NAS | 外から見られる設定で、NAS 自体が直接暗号化される |
| 保守業者のリモート接続 | 業者が入れた遠隔操作ソフトが常駐している、業者の回線が常時つながっている |
| クラウドのアカウント | Microsoft 365 や Google のアカウントが乗っ取られる |

**(4) 慎重なリモート接続も、電話一本で崩される**

2026年5月から急増した手口（本文 p.19）:

1. 銀行や業者を名乗って会社に電話をかける
2. 「手続きのため」と遠隔操作ソフトを社員に入れさせる
3. その PC を遠隔操作しながら、偽サイトでネットバンキングの ID・パスワードを盗み、送金する

会社の方針が慎重でも、現場の一人がだまされれば正規のリモート接続が攻撃者の手に渡る。
普段使っている PC から送金されるので、銀行の不正検知もすり抜ける。

**(5) 狙いが自社ではないこともある**

中小企業は、取引先の大企業への**踏み台**として狙われる。
自社の被害は小さくても、取引先への影響で責任を問われることがある。

## 6. 対策チェックリスト

### 入口をふさぐ

- [ ] VPN 機器・ルーター・NAS のファームウェアが最新か
- [ ] 管理画面がインターネットから開けないか
- [ ] リモート接続に多要素認証が付いているか
- [ ] リモートデスクトップをインターネットへ直接公開していないか
- [ ] 退職者や保守用の使っていないアカウントが残っていないか

### 広がらせない

- [ ] 共有フォルダーの書き込み権限を、必要な人だけに絞っているか
- [ ] PC ごとにローカル管理者のパスワードが違うか（Windows LAPS で自動化できる）
- [ ] 保守業者のものも含め、常駐しているリモート接続ソフトを把握しているか

### 壊されても戻せる

- [ ] バックアップが PC や NAS から書き換えられない形で保管されているか
  （オフライン、書き換え不可、NAS のスナップショットなど）
- [ ] バックアップから実際に戻せるか、定期的に試しているか

### 人をだまさせない

- [ ] 「電話で言われてソフトを入れない」を社内ルールにしているか
- [ ] 送金先の変更や急な送金依頼は、折り返し電話で確認する決まりがあるか
- [ ] SNS グループの作成を指示されたら疑う、と周知しているか（ニセ社長詐欺対策）

中小企業ではとくに**共有フォルダーの権限**と**切り離したバックアップ**を押さえておけば、
PC が1台感染しても業務データを失わずに済む可能性が大きく上がる。
